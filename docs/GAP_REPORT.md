# GAP REPORT — Frontend Schema ↔ Backend Models

> Generated by Phase 0 audit.  
> **Fix-side rule**: default = change the backend model + add migration. Change frontend mapping only if the field is purely cosmetic or redundant.

---

## 0. Structural Differences

| Concern | Frontend | Backend | Decision |
|---------|----------|---------|----------|
| **Passwords** | PBKDF2-SHA256 via Web Crypto (hex hash + hex salt stored as two fields: `passwordHash`, `salt`) | Django `make_password`/`check_password` (PBKDF2 + base64, single `password_hash` field) | ✅ **Keep backend's Django hashers** — they are more secure. Seed command will use `make_password`. Frontend `salt` field is irrelevant to backend. |
| **Role storage** | String enum on user record (`ADMIN`, `DOCTOR`, `RECEPTIONIST`, `PHARMACIST`, `LAB_TECH`) | FK to `Role` table (role_id = PK) | ✅ **Keep FK** but serializer exposes `role` as the string `role_id`. Seed must create Role rows first. |
| **Doctor as entity** | Frontend has NO separate Doctor entity — a staff record with `role='DOCTOR'` IS the doctor. `doctorId` fields point to `staff.id`. | Backend has a separate `Doctor` model 1:1 with `Staff`, with its own `doctor_id`. Appointment.doctor FK points to `Doctor`, not `Staff`. | ⚠️ **Major gap**. Fix: keep `Doctor` model but all API responses must expose `staff_id` as the doctor identifier used by frontend. The serializer must accept staff-level IDs and resolve to Doctor internally. |
| **Money** | Paise (integer) — e.g. `50000` = ₹500 | `DecimalField(max_digits=10, decimal_places=2)` — e.g. `500.00` | ✅ **Keep Decimal** on backend. Serializer converts: `paise = int(value * 100)` for frontend, and frontend sends paise which serializer converts to Decimal for storage. |
| **Versioning** | Every record has `_v` (optimistic lock counter) | Not present | Add nothing — DRF will use standard DB-level locking. Frontend `_v` field was only for localStorage concurrency. |
| **ID formats** | `dept-01`, `staff-doc-01`, `pat-01`, `appt-001`, etc. (string) | Auto-generated via `IdSequence`: `DEPT-0001`, `STF-0001`, `PAT-2026-0001`, etc. | ✅ **Keep backend IDs**. Seed command will use explicit IDs matching seed data for demo consistency. |
